# Toolchain spike golden reports

These normalized reports are generated by:

```bash
./container/run.sh ./fixtures/pass-through/verify.sh
```

They compare the unmodified SDK C++ dummy with the manual Rust pass-through
unit built by the same GNU final linker and `unit.ld`. Paths are replaced with
`<WORKSPACE>`; executable bytes are not checked in here. The loadable Rust ELF,
map, reports, and hash are generated under `target/nts3/pass-through/`.

The empty Rust `.rel.plt` output section is created by the SDK linker script,
but has zero size and no corresponding `.plt`; the Rust unit has no dynamic
relocations or undefined symbols. The C dummy's non-empty PLT is retained as a
baseline observation, not copied into the Rust design.

Hardware testing also established a non-obvious loader invariant: every
required callback must have a distinct dynamic-symbol address. LLVM's default
MergeFunctions aliases for identical empty callbacks caused silent rejection.
The build uses `-mergefunc-use-aliases=0`, and `verify.sh` rejects callback
aliases or missing Thumb bits.
